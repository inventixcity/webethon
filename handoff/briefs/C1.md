# C1: exam_questions (question bank + question import)
Crate: `backend/crates/exam_questions`. Mount everything in `pub fn router() -> Router<AppState>` (paths are relative to `/api/v1`).
Implement the C1 rows of the HANDOFF API contract with shapes `Question`, `QuestionInput`, `ImportResult`, and `Page<Question>` from `web/src/lib/exam/types.ts`.

- Examiner or admin only (`examcore::ExaminerViewer`). An examiner sees only their own questions, an admin sees all, and anything else is a 404.
- Validation, the same on create, PATCH and import:
  - topic 1-80 chars, trimmed; difficulty 1-5; kind single|multi|written; stem 1-4000 chars
  - options: 2-10 items for objective kinds, each with a unique id (`^[a-z0-9]{1,8}$`) and text 1-500 chars; written questions have no options
  - `correct` ids must exist among the options; single has exactly 1 correct, multi has at least 1
  - marks 0 < m <= 1000 in 0.25 steps; 0 <= negativeMarks <= marks; multiRule from the enum
  - rubric up to 4000; maxWords 1-5000 or null; explanation up to 4000
  - Return `examcore::invalid_many` with precise paths (for example `options[2].text`).
- PATCH requires an `If-Match: <version>` header. Return 428 if it's missing and 409 `VERSION_CONFLICT` if it's stale. Bump `version` and `updated_at`. DELETE is a soft delete (`deleted_at`). Editing never affects published exams, because papers are snapshotted in `exam_items`.
- List: filters topic, difficulty, kind, and q (ILIKE on stem and topic, with `%` and `_` escaped). Keyset pagination on (created_at desc, id) with an opaque cursor; limit defaults to 25, max 100. `GET /questions/topics` returns `{topic, count}`.
- `POST /questions/import {rows, dryRun}`:
  - At most 500 rows. Validate every row and collect all errors as `{row (1-based), path, message}`.
  - If `dryRun` is set, or there are any errors, write nothing. Otherwise insert every row in one transaction.
  - Rate limit with a 20/hour per-user budget via `kernel::security::enforce_rate_limit`.
  - Accept two row shapes:
    1. `QuestionInput` objects.
    2. Flat CSV-style rows: `{topic, difficulty, kind, stem, optionA..optionF, correct: "A,C", marks, negativeMarks?, multiRule?, rubric?, maxWords?, explanation?}`. Numbers may arrive as strings. Detect this shape per row (presence of `optionA` or a string `correct`) and map option letters to ids a..f.
- Audit create, update, delete and import (`questions.create`, `questions.update`, `questions.delete`, `questions.import`).
- Tests:
  - validation failures
  - another examiner's question gives 404
  - a candidate gets 403
  - the If-Match flow
  - an import dry run writes nothing
  - an import with one bad row writes nothing
- Also add 30 realistic demo questions to `backend/crates/exam_questions/seed/questions.json` as an array of QuestionInput objects:
  - topics: Data Structures, Algorithms, Databases, Computer Networks, Web Security
  - a mix of difficulties 1-5 and of the single, multi and written kinds
  - 6 written questions with rubrics
  - plus `web/public/samples/questions-sample.csv`, a 6-row CSV in the flat format, for the import demo
- C8's seed command loads `seed/questions.json`; expose it with `pub const SEED_QUESTIONS: &str = include_str!("../seed/questions.json");` and a pub fn `insert_question(tx, owner_id, input)` that the seed can reuse.
