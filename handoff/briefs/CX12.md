# CX12: Streamlined, dynamic navigation. Web only.
First read handoff/briefs/_common-ui.md.

The user said: "the navbar needs improvements, like a streamlined dynamic navbar that responds to clicks and differentiates what is selected, matching the theme of the web."

You own:
- web/src/components/app-shell/** (the sidebar, the mobile top bar and drawer CX9 built, and the breadcrumb bar)
- web/src/components/exams/exam-tabs.tsx
- the shared tab and segmented components in web/src/components/ui/** (keep the APIs stable)
- the public site header or nav component (the landing, verify and contact top bar; if it's inline in web/src/app/page.tsx, extract it to web/src/components/marketing/site-nav.tsx and import it — CX7 is editing page.tsx, so make that a minimal, surgical edit)

Make navigation feel alive and unambiguous:
1. **App sidebar:**
   - A sliding active indicator: a cobalt bar plus a filled ink row that animates between items on route change (a CSS transform on one indicator element measured from the active link; no layout thrash).
   - Hover fill wipe, matching the buttons.
   - Pressed feedback on click (a quick scale or offset, no wiggle).
   - Keyboard focus rings.
   - Group headings with counts where cheap (e.g. Exams (6)).
   - Collapsible to icon-only on desktop, with tooltips and the state remembered in localStorage (wrapped in try/catch).
   - The current section stays obvious at a glance: icon tinted, label bold, and `aria-current="page"`.
2. **Mobile top bar and drawer (from CX9):** the same active styling, with the drawer items animating in.
3. **Exam tabs and filter bars:** the same sliding indicator under or behind the active tab (`transform: translateX` plus width), scrolling the active tab into view on mobile.
4. **Breadcrumb bar:**
   - clickable crumbs
   - the current page in ink-bold
   - a small live "ONLINE" status already there, kept
5. **Public nav:**
   - a sticky, compact header that condenses on scroll, with a hairline under it
   - the active link underlined with a cobalt bar
   - a "Contact" link and a Sign in button (the Button component)
   - Use a mobile menu at small widths.
6. Respect prefers-reduced-motion (no sliding, just an instant state change). Both themes. No layout shift on route change.

Verify by clicking through the routes in headless Chrome. Screenshot the indicator positions on several routes at 1440 and 390, in both themes.
