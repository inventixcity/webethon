Charts (custom SVG, matching the site):
- square, hairline axes, mono tick labels
- ink, cobalt and amber series
- readable in both themes; respect prefers-reduced-motion
- an accessible `<title>`/`<desc>` and an sr-only table
- tooltips on hover and focus
- smooth transitions when data updates (no jank), a sensible empty state
- responsive with ResizeObserver; fine at 390px

Where to put them:
1. **Monitor (live):**
   - an "Activity" line or area chart over the exam window: answers saved per minute, active candidates, connection drops per minute
   - a stacked bar of status counts (not started / in progress / submitted)
   - Update them live from the existing SSE monitor stream (`/exams/{id}/monitor/stream`) or its snapshot data; add a server timeseries endpoint if needed (e.g. GET /exams/{id}/monitor/timeseries?bucket=60).
2. **Examiner overview dashboard:**
   - submissions over the last 7 days (bars)
   - a live "candidates in exams right now" sparkline with a pulsing live dot (polls every 15s or uses SSE)
   - pass rate per recent exam (horizontal bars)
3. **Admin overview and system:**
   - sign-ins per hour over the last 24h
   - active sessions now
   - API error rate and latency p50/p95, if derivable from the audit log or existing tables (otherwise omit)
   - accounts by role (a stacked bar)
   - Auto-refresh every 30s.

Backend rules:
- every endpoint uses the correct viewer extractor (examiner owns the exam; admin only for admin data), returning 404 for not-visible
- bounded query ranges, aggregated in SQL
- the `{data}` envelope with RFC 3339 timestamps
- run fmt, `clippy --all-targets -D warnings` and the crate tests
Keep the API calls efficient: no N+1, and add indexes in a migration if needed.
