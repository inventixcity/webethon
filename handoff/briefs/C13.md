# C13: 5.2 Fair randomised papers (backend)
You own the blueprint parts of `backend/crates/exam_authoring/**` and the attempt paper-draw in `backend/crates/exam_attempts/**`, plus migrations `20261127002000_*`. Read handoff/HANDOFF.md ("PHASE 2", section 5, USER UI RULES) and the PHASE 2 types in web/src/lib/exam/types.ts (Blueprint, BlueprintPreview, FairnessReport).

Design (examiners need fairness across candidates while each still gets a different paper):
1. Migration: table `exam_blueprints(exam_id pk → exams, enabled bool, rows jsonb, tolerance numeric(4,3) default 0.05, updated_at)`. Add `attempts.predicted_facility numeric(5,4)` (nullable). Enable RLS on new tables (as the core migration does).
2. Difficulty estimate per item: use `questions.observed_facility` when `observed_count >= 5`, else map declared difficulty 1..5 to facility 0.85, 0.7, 0.55, 0.4, 0.25. Snapshot this estimate into a new column `exam_items.predicted_facility` at publish (update C2's publish snapshot SQL in exam_authoring).
3. Endpoints, all `{data}` via examcore::ok, exam owner via load_exam_for_examiner:
   - GET/PUT `/exams/{id}/blueprint`. PUT is draft only; validate rows (topic must exist in the exam's assigned questions; difficulties 1–5 with min ≤ max; count ≥ 1; marksEach > 0, 0.25 steps; tolerance 0.01–0.3). Total marks = Σ count × marksEach must equal exam totalMarks for the review to pass. Add a check to C2's review checklist when enabled.
   - GET `/exams/{id}/blueprint/preview`: simulate 50 papers with the same draw algorithm (seeded) and return BlueprintPreview. `feasible` is false (with `problems`) if any row lacks enough questions in the pool. fairnessScore = round(100 × (1 − min(1, spread / 0.3))).
   - GET `/exams/{id}/fairness` → FairnessReport from real attempts (predicted_facility, observed percent where graded).
4. Draw at attempt start (exam_attempts, inside the existing start transaction, ONLY when the blueprint is enabled):
   - For each row, take the published exam_items matching topic and difficulty band, and draw `count` with the attempt seed (examcore::shuffle).
   - Retry up to 200 seeds-derived variants to bring the paper's mean predicted facility within `tolerance` of the pool target (mean of the per-row expected facility). Pick the closest if none qualifies.
   - Store item_order (and the per-item marks override = marksEach) so grading uses the blueprint marks. Store per-attempt marks in a new column `attempts.item_marks jsonb` ({"<item id>": marks}). Do NOT edit exam_grading (C14 owns it and will make autograde honour `attempts.item_marks`). Your test for 'grading uses the override marks' can assert the stored overrides.
   - Set attempts.predicted_facility.
   - Non-blueprint exams behave exactly as before.
5. Tests: a feasible blueprint draws N items per row; the spread of 50 seeded papers is ≤ tolerance where the pool allows it; draft-only PUT; another examiner gets 404; non-blueprint exam start is unchanged; per-attempt marks are stored.
6. `bash scripts/cargo.sh fmt --all`, plus clippy for your crates with `--all-targets -- -D warnings`, plus tests. Don't break existing tests.
Finish with `STATUS: COMPLETE` as the last line of handoff/log/C13.md.
