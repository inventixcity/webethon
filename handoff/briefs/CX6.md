Fix:
1. **Branding on every PDF page.**
   - A header band with the Inventix Invigil mark (an ink square with a vermilion notch, then "INVENTIX INVIGIL" in mono caps) and the institute name.
   - A footer: "Issued by <institute> · Generated by Inventix Invigil", page X of Y, generation time (PKT) and the verify URL.

2. **An engaging layout matching the site:** ivory paper, ink rules, and cobalt and amber accents. Embed the site fonts if feasible, otherwise use Helvetica and Courier.
   - **Candidate result statement:**
     - a title block (exam, candidate, date)
     - a big score and percent, with a PASS / NOT PASSED stamp
     - a per-question breakdown table with zebra rows and marks bars
     - a verify-code box and a QR code (add `qrcode` if no encoder exists)
     - a signature and seal block
   - **Exam report:**
     - a cover summary with KPIs (enrolled, submitted, mean, median, pass rate)
     - a score distribution bar chart drawn as vector rects
     - a per-candidate table that paginates cleanly and repeats its header row
     - an item analysis table
3. **File names.**
   - `<exam-title-slug>_<candidate-name-slug>_result.pdf`
   - `<exam-title-slug>_report_<YYYY-MM-DD>.pdf`
   - CSVs: `<exam-title-slug>_results_<YYYY-MM-DD>.csv`
   - Use an ASCII slug of at most 80 chars, and also send the RFC 5987 `filename*`. Never put ids in names.
4. Keep the auth checks exactly as they are: the examiner owns the exam, and the candidate owns a published attempt. Update the route tests.
