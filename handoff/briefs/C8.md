# C8: exam_analytics (3.8 summaries, 4.5 question analytics, 5.1 collusion indicator), admin roles, demo seed

## Backend: `backend/crates/exam_analytics`

**`GET /exams/{id}/analytics`** (exam owner): `ExamAnalytics` from real, finalized attempts only.
- Score stats: mean, median, stdDev (population), highest, lowest, passRate, a 10-bucket percent histogram.
- Reliability: KR-20 for objective items (alpha-like for mixed: use Cronbach's alpha on item score proportions), null if fewer than 3 attempts or no variance.
- Per item (`ItemAnalytics`):
  - facility = mean awarded / marks (clamped 0..1)
  - discrimination = upper 27% facility − lower 27% facility, by total score (null if fewer than 4 attempts)
  - skipRate = share of attempts with no answer or an empty response
  - option pick counts with a correct flag (distractor analysis)
  - flags:
    - too_easy: facility > 0.9
    - too_hard: facility < 0.2
    - negative_discrimination: < 0
    - often_skipped: skipRate > 0.25
    - dead_distractor: a wrong option with 0 picks when attempts >= 5
- Topics: mean percent per topic.
- similarPairs (5.1 collusion indicator, the Harpp–Hogan-style "identical wrong answers"): for each pair of attempts, count objective items where both answered identically AND wrongly. `ratio = identicalWrong / max(1, items both got wrong)`. Return the pairs with identicalWrong >= 3 and ratio >= 0.75, top 20, labelled with display names. Compute it in Rust in memory (fine for <= 500 attempts; cap at 500 and note it).
- After computing, update `questions.observed_facility` and `observed_count` for the source questions (via exam_items.question_id) with a running weighted average. This is the bank's "observed difficulty".

**`GET /questions/{id}/stats`** (owner): per-exam facility and discrimination history for that bank question.

Tests: stats on a fixed fixture; the collusion pair is detected; sandbox is excluded; another examiner gets 404.
