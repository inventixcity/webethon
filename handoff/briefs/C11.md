# C11: institution-driven password reset (admin crate)
Product rule: there is NO self-service "forgot password" email (those auth routes are now disabled). A user who forgot their password asks their institution. An admin, or the examiner for their own candidates, issues a fresh access link.

You own `backend/crates/admin/src/users.rs` (and a new `backend/crates/admin/src/access.rs` if you prefer) plus `backend/crates/exam_enroll/src/lib.rs` ONLY for the candidate re-issue endpoint described below. Read handoff/HANDOFF.md section 5, the existing `POST /admin/users` (it already creates invites in `account_invites`), and the invite-accept flow in exam_enroll (`/invites/{token}`, `/invites/accept`; accept currently requires `password_hash is null`).

Implement:
1. `POST /api/v1/admin/users/{id}/reset-access` (admin only, step-up rules as the other admin user actions use, audited `admin.reset_access`):
   - In one transaction:
     - set the user's `password_hash = null` and `password_changed_at = now()`
     - revoke all their sessions (`update sessions set revoked_at=now() where user_id=$1 and revoked_at is null`)
     - invalidate earlier unused invites
     - create a new `account_invites` row: 72 h expiry, hashed token from `kernel::crypto::new_token`
   - Return `{"data":{"inviteUrl":"<APP_ORIGIN>/invite/<token>","expiresAt":"<rfc3339>"}}` (envelope via `examcore::ok` or json `{data}`).
   - Do NOT send any email: the admin hands the link over.
   - An admin can't reset their own access this way (422) and can't reset the last other admin (keep existing safety rules).
   - Rate limit at 10/hour per admin.
2. `POST /api/v1/exams/{examId}/enrollments/{candidateId}/reset-access` in exam_enroll: the same behaviour for the exam owner, restricted to candidates (`role='user'`) enrolled in that exam (404 otherwise). It returns `{inviteUrl, expiresAt}` and sends no email. Audited `exam.reset_access`.
3. Make sure `GET /invites/{token}` and `POST /invites/accept` work for a reset user. The user exists and is activated-then-reset, with password_hash now null, so accept succeeds.
4. Tests:
   - a non-admin gets 403/404
   - reset revokes sessions and nulls the password
   - the new link works exactly once
   - an old link is invalid
   - no email is sent (use a test sender that counts)
5. `bash scripts/cargo.sh fmt -p admin -p exam_enroll`, plus check and test.

Finish with `STATUS: COMPLETE` as the last line of handoff/log/C11.md. The web UI is built by another worker against exactly this contract.
