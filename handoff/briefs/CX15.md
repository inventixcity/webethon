## Backend (exam_settings)
- **Table `user_preferences`:** user_id pk/fk, prefs jsonb, updated_at. RLS lockdown like the other migrations.
- **GET/PATCH /api/v1/me/preferences** (any signed-in user). The schema is validated per role, with deny_unknown_fields and bounded values; PATCH merges.
  - **All roles:** theme (system|light|dark), reducedMotion (bool), textSize (sm|md|lg), timeZone (an IANA name validated against a list, default "Asia/Karachi"), emailNotifications { securityAlerts (always true; read-only), productUpdates (bool) }.
  - **Candidate:** accessibility { highContrast, dyslexiaFont, largerTargets, confirmBeforeSubmit (default true) }, examReminders { emailBeforeStartMinutes: 0|15|60|1440 }.
  - **Examiner:** examDefaults { durationMinutes 5–600, passPercent 0–100, shuffleQuestions, shuffleOptions, lateJoinMinutes 0–120, integrity { fullscreen, pasteBlock, focusTracking, typingTelemetry } }, notifications { onSubmissionsComplete, onDisputeFiled, onOutageReported }.
  - **Admin:** notifications { onInstituteRequest, onSecurityEvent }.
- **Table `institution_settings`:** a single row, id=1 with a check constraint.
- **GET /api/v1/institution** (public subset: name, shortName, contactEmail, supportHours) and **GET/PATCH /api/v1/admin-institution** (admin only, 404 otherwise; PATCH requires a recent step-up; reuse the existing step-up check pattern from the admin crate by calling its public helper if one exists, otherwise copy the same 428 STEP_UP_REQUIRED behaviour). Fields:
  - name, shortName, contactEmail, supportHours
  - defaultTimeZone
  - aiSuggestionsEnabled (bool)
  - allowCandidateSelfDelete (bool)
  - staffMfaRequired (bool; stored only, and flagged in the UI as "applies at next sign-in" only if enforced — otherwise label it "coming soon"; do not pretend)
  - resultsVerificationPublic (bool)
  - Audit-log every change, including the old→new diff.
- Expose `pub async fn ai_suggestions_enabled(db) -> bool` and `pub async fn institution_name(db) -> String` for the lead to wire later.
- **Tests:** validation per role (an examiner can't set candidate fields, etc.), admin-only access, step-up enforcement, audit entries.

## Web: /app/settings, role-aware
- **A left sub-navigation** (sticky on desktop; a horizontal scrollable chip bar on mobile) with sections that depend on role:
  - **Everyone:** Profile, Appearance & accessibility, Notifications, Security (password, two-step), Devices.
  - **Candidate:** + Exam preferences (accessibility toggles, reminders); Delete account only if the institution allows it.
  - **Examiner:** + Exam defaults (prefilled into the New exam form — expose a hook `useExamDefaults()` in web/src/features/account; the lead will wire it into exam-form).
  - **Admin:** + Institution (name, contact, support hours, time zone), Policies (AI suggestions, self-delete, public verification, staff MFA), and links to Users, Audit and Requests.
- Each section is a card with a numbered eyebrow, inline save, an optimistic "Saved" state, and errors via the toast stack.
- Appearance applies immediately: theme, reduced motion via a data attribute on `<html>`, and text size via a root font scale.
- **Devices:**
  - parse the user agent into "Chrome on Windows", "Safari on iPhone", etc. (a small, dependency-free parser)
  - show the current device first with a "This device" badge
  - show 5, then "Show all (N)"
  - group older-than-7-days sessions under "Older"
  - revoke per row, plus "Sign out of other devices"
  - empty and loading states
- Use the shared UI primitives, Switch/Toggle for booleans, segmented chips for enums. Both themes; good at 390px.
