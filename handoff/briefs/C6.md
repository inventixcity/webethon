# C6: exam_grading (auto and manual grading, results publication, verifiable certificates, PDF reports)

## Backend: `backend/crates/exam_grading` (C4 depends on you, so ship `autograde_attempt` FIRST, within the first 15 minutes, so C4 compiles)

**`pub async fn autograde_attempt(conn: &mut sqlx::PgConnection, attempt_id: Uuid) -> AppResult<()>`**:
- Load the attempt's items (through item_order) and the answers.
- For objective items: `auto_marks = examcore::score_objective(MarkingScheme{...}, selected)`. Unanswered items count 0 without an answer row.
- Written items keep their manual_marks.
- Set:
  - `auto_score` = sum of objective marks
  - `manual_score` = sum of graded written marks
  - `total_score` = max(0, auto + manual), rounded to 2 dp
  - `grading_status` = complete if there are no written items or all are graded; partial if some are; pending otherwise
- Idempotent; re-running gives the same numbers.

**`GET /exams/{id}/grading?pending=true&itemId=`** (exam owner): `GradingItem[]` for the written answers of finalized real attempts.
- Blind by default: `scriptLabel` = "Script NN" from a stable order (attempt created_at). Never include the candidate name.
- Include rubric, marks, answer text and word count.

**`PUT /attempts/{id}/answers/{itemId}/grade {marks, feedback}`** (exam owner):
- The attempt must be finalized and the item written.
- 0 <= marks <= item marks, in 0.25 steps; feedback <= 4000 chars.
- Results must not be published (409 reason `published`; unpublish first).
- Lock the attempt, set manual_marks, feedback, graded_by and graded_at, re-run autograde_attempt, and audit `grading.grade` with the before and after marks.
- An answer row may not exist for a skipped written item: insert one with an empty text response, so the grade can be stored.

**`GET /exams/{id}/results`** (owner): `ExamResults`.
- Real attempts only. percent = total / exam total_marks * 100; passed = total >= pass_marks.
- `canPublish` requires all of: window closed or exam completed; no in_progress attempts; all attempts grading_status complete.
- `blockers` lists human-readable reasons.

**`POST /exams/{id}/results/publish`**:
- Lock the exam and require canPublish. Set `results_published_at`.
- For every real finalized attempt, issue a `result_certificates` row:
  - `verify_code`: 12 chars of Crockford base32 from OsRng, formatted `XXXX-XXXX-XXXX`
  - `statement` JSON: certificateId (verify_code), examTitle, candidate masked as first initial + ". " + first letter of the last name + "****" + last letter, percent, passed, issuedAt, issuer "Inventix Invigil"
  - `statement_hash = sha256(examcore::canonical_json(statement))`
  - `signature = examcore::signer::sign(statement_hash)` and `key_id`
- Idempotent (`on conflict do nothing`). Audit it.
- `/results/unpublish`: clear results_published_at and set `revoked_at` on the certificates.

**`GET /me/results/{attemptId}`** (candidate, own, results published): `CandidateResult`.
- The breakdown only when settings.showBreakdown is true. Include correct keys, explanation and feedback only then.
- Never return another candidate's data (404).

**`GET /verify/{code}`** (public, no auth):
- Rate limit at 30/min per IP. Normalise the code (uppercase, strip spaces, accept with or without dashes).
- Look up the certificate, recompute the hash from the stored statement, and verify the signature.
- Return `VerificationResult` with ONLY the masked statement (never the email, the id or the answers). An unknown code is valid:false with a 200 (no timing leak beyond the DB lookup).

**`GET /attempts/{id}/report`** (candidate own after publish, or exam owner) and **`GET /exams/{id}/report`** (owner): JSON for the PDFs.
- Attempt report: candidate name (full, for the owner and the candidate themselves), exam, score, percent, pass, per-question marks, verify code, and the public verify URL `${APP_ORIGIN}/verify/<code>`.
- Exam report: summary stats (count, mean, median, highest, lowest, pass rate), the rows table, and the item summary (facility per item).

Tests:
- multi-select rules through autograde
- grade validation (above max, wrong step)
- a candidate can't see an unpublished result
- the verify signature passes, and fails after tampering with the statement in the DB
- publish blocked while grading is incomplete
