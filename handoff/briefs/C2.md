# C2: exam_authoring (exam lifecycle, paper assignment, review, publish, sandbox)
Crate: `backend/crates/exam_authoring`. Implement the C2 rows of the contract with `Exam`, `ExamSummary`, `ExamInput`, `ExamSettings`, `ExamReview` from `web/src/lib/exam/types.ts`.

- Examiner or admin only, and the owner only, via `examcore::load_exam_for_examiner` (404 otherwise). An admin lists all exams.
- Phase comes from `examcore::phase` with the server clock. Parse settings with serde defaults and `deny_unknown_fields`:
  - shuffleQuestions true, shuffleOptions true, allowOfflineJournal true
  - lateJoinMinutes null, or 0-1440
  - showBreakdown true
  - integrity {watermark true, canary false, fullscreen true}
- Validation: title 1-160; instructions up to 8000; endsAt > startsAt; durationMinutes 1-1440 and <= the window length; totalMarks 0 < x <= 100000; 0 <= passMarks <= totalMarks.
- PATCH needs `If-Match: <version>`. Editable fields depend on the exam's state; every change is audited:
  - draft: anything
  - published, before start: only title, instructions and endsAt (an extension only)
  - ongoing or later: only instructions and an endsAt extension
- `PUT /exams/{id}/questions {items:[{questionId, marks?}]}`: draft only. Replace the assignment with up to 200 questions, all owned by the viewer (admin: any) and not deleted, with no duplicates. `position` is the array order and `marks` is an optional override.
- `GET /exams/{id}/review` returns an `ExamReview` with these checks:
  - has a title
  - has 1+ questions
  - assigned marks equal totalMarks exactly (the message shows both numbers)
  - the window end is in the future
  - the duration fits the window
  - at least 1 enrolled candidate (a warning only: ok=false must not block `ready`; use key `candidates`)
  - objective questions have keys
  - Also return the topic and difficulty mix.
- `POST /exams/{id}/publish`:
  - Lock the exam row `for update`. Require ready=true and draft status.
  - Snapshot every assigned question into `exam_items` (sandbox=false) inside the same transaction, using the override marks if set.
  - Set status published and published_at, and bump version.
  - Idempotent: publishing an already published exam returns it unchanged.
- `POST /unpublish`: only when there are no real attempts. It deletes the real items and returns the exam to draft.
- `POST /complete`: once the window has closed, or with `?force=true` for the owner. Set status `completed` and `completed_at`. Don't depend on other exam crates: the attempt sweep finalizes stragglers.
- `POST /duplicate`: copies the exam as a draft titled "<title> (copy)" with the same assignment and a window shifted to start tomorrow.
- `POST /exams/{id}/sandbox`: the owner, any status (4.3).
  - In one transaction, delete the owner's previous sandbox attempt and the sandbox items for this exam.
  - Insert `exam_items` with sandbox=true, from the current assignment (draft) or by copying the real items (published).
  - Create an `attempts` row:
    - sandbox=true, candidate_id = the examiner, deadline = now + duration
    - `seed` from `rand::rngs::OsRng`
    - `item_order` and `option_order` built with `examcore::shuffle` according to the settings; `option_order` maps the item id to a list of option ids
    - `journal_genesis` set to 32 random bytes; `active_device` null
  - Return `{attemptId}`.
  - Sandbox rows never count in results, analytics or monitoring (other crates filter `not sandbox`).
- `GET /exams/{id}` includes `questions` with full Question objects (draft: from `exam_questions` joined to `questions`; published: from `exam_items` with `questionId` = question_id). It also includes enrolledCount, attemptCount (real only), questionCount and phase.
- Tests:
  - publish is blocked when marks don't add up
  - publish snapshots the paper, so a later bank edit doesn't change the paper
  - another examiner gets 404
  - the PATCH rules after publish
  - sandbox attempts are excluded from attemptCount
  - unpublish is refused when attempts exist
- Expose `pub async fn create_exam_tx(...)`, `pub async fn assign_tx(...)` and `pub async fn publish_tx(...)` helpers so C8's demo seed can reuse them.
