# CX13: Beautifully formatted emails across the product. Backend (Rust).
First read handoff/briefs/_common-ui.md. The visual and encoding rules apply.

The user said: "every email sent from us must be beautifully formatted", and "we must receive the actual email in our info@inventixhq.com email" for contact requests.

You own:
- a new shared email module in backend/crates/kernel (e.g. `kernel::email_layout`), or a small new crate `mailkit` if kernel has no mail module
- every place that builds an email body. Find them with `grep -rn "subject\|html" backend/crates/{auth,admin,exam_enroll,exam_contact,exam_grading,exam_disputes}/src`; known spots are auth/src/emails.rs, exam_enroll (invites, `fn html`), admin (account invites, reset access) and exam_contact (the institute request notification plus the acknowledgement).
Do not change who gets emailed or when. Change only the content, layout and text alternative.

## Design (table-based, inline styles, works in Gmail, Outlook, Apple Mail and dark-mode clients)
- **Palette:** ivory #F3EEE3 page, white #FFFFFF card with a 1px ink #12110E border (square corners), ink text, muted #5E5A52, cobalt #2B4FD8 links and accents, vermilion #D23A1C for the mark and alerts, amber #E0862C sparingly.
- **Fonts:** a Helvetica/Arial stack for the body; a "Courier New" monospace stack for eyebrows, codes and labels.
- **Header:** a brand bar with the mark (a 20px ink square with a vermilion notch via a nested table cell) and "INVENTIX INVIGIL" in mono caps with letter-spacing, then a thin cobalt rule.
- **Body:** a mono-uppercase eyebrow (e.g. "SECURITY / VERIFY EMAIL"), a large heading, then paragraphs.
- **Primary CTA:** a bulletproof square button (ink background, ivory text, mono caps), with the raw URL repeated below in small text.
- **One-time codes:** a big spaced mono block in a bordered box, plus an expiry line.
- **Key-value detail table:** the contact request fields, the exam name and window, the candidate, etc.
- **Footer:**
  - a muted line on why they got it
  - the "Inventix Invigil · Exams that hold up." line
  - the contact email, "COMSATS University Lahore, Pakistan"
  - a security note ("We never ask for your password by email.")
- **Hidden preheader text.** Also `<meta name="color-scheme" content="light only">` and `supported-color-schemes`.
- **Plain-text alternative** for every email, sent as multipart if the mailer supports it. Check how Resend is called: the `text` field.
- **Escape EVERYTHING user-supplied** (names, institute, message): HTML-escape, and escape URLs in attributes. Convert newlines in the message to `<br>` only after escaping. Keep subjects free of CR/LF.

## Emails to cover
- **Auth:** sign-in or verify-email code, password reset code or link, new-device or security notices (if any).
- **Admin-created account invite and reset access.**
- **Candidate enrolment invite** (with the exam title, window and the accept link).
- **Results published, and dispute resolved** (if these send emails).
- **Contact:**
  - the notification to the inbox in the env `CONTACT_INBOX` (default `info@inventixhq.com`), with every field in a detail table and Reply-To set to the requester
  - the acknowledgement to the requester
  - Make sure the notification really goes to info@inventixhq.com in production: it must use the configured Resend sender (EMAIL_FROM is already `Inventix Invigil <info@inventixhq.com>`).

## Tests
- snapshot-style tests that each template contains the escaped values and no raw `<script`
- that the text alternative exists
- that a subject with CR/LF is rejected or sanitised

Run fmt, `clippy --all-targets -D warnings`, and the tests for every touched crate.
