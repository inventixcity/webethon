# C3: exam_enroll (enrollment, candidate provisioning, invites)
Crate: `backend/crates/exam_enroll`. Implement the C3 rows of the contract with `Enrollment`, `CandidateImportRow`, `ImportResult`.

- Enrollment endpoints: exam owner or admin, via `examcore::load_exam_for_examiner`.
- `POST /exams/{id}/enrollments {candidates:[{email, displayName, extraMinutes?}], invite, dryRun}`:
  - At most 1000 rows. Validate the email (lowercase, trimmed, <= 254 chars, sane shape), displayName 1-120, and extraMinutes 0-600.
  - Row errors: duplicates within the file; an existing user whose role is examiner or admin ("not a candidate account").
  - Create missing users with role `user`, no password and email_verified_at null.
  - Upsert the enrollment: re-enrolling a revoked candidate sets it back to enrolled.
  - With dryRun, or when there are any errors, write nothing. Run everything in one transaction.
  - Rate limit at 30/hour per examiner.
  - Response: `ImportResult` plus `inviteLinks`.
- Invites (accounts are provisioned, never self-registered):
  - Trigger: for each new or never-activated candidate when `invite` is true, and from `POST /exams/{id}/enrollments/{candidateId}/invite` (rate limited at 10/hour per candidate).
  - Token: create an `account_invites` row with a token from `kernel::crypto::new_token()`. Store only its hash, set a 7-day expiry, and invalidate earlier unused invites for that user.
  - Email: send the link `${APP_ORIGIN}/invite/<token>` (APP_ORIGIN is in `state.config`) with `state.email.send(&kernel::email::Email{..})`. Write a clean HTML and text email from "Inventix Invigil" that mentions the exam title and schedule, and HTML-escape all interpolated values.
  - Send after commit. A failure is logged, never fatal.
  - **Return the invite URLs in the response to the exam owner only**, as `inviteLinks: [{email, url}]`. The UI shows them once, so the demo works even without email. Never store the raw token.
- `GET /auth/invites/{token}`: public, rate limited per IP (`limits::CODE_PER_IP`, using the client IP from `kernel::request::RequestMeta`). Returns `{email, displayName}` if the invite is valid and unused, otherwise 404.
- `POST /auth/invites/accept {token, password, displayName}`:
  - Password policy: hash with `auth::password::hash`, and reuse the auth crate's policy check (find it in `backend/crates/auth/src/password.rs`).
  - Mark the invite used atomically (`update ... where used_at is null and expires_at > now() returning user_id`).
  - Set password_hash, email_verified_at=now() and display_name.
  - Create a session exactly the way the auth crate's sign-in does (read `backend/crates/auth/src/routes.rs` and `kernel::session`), including the Set-Cookie header.
  - Audit it as `auth.invite_accepted`.
- Routing: the auth router is nested at `/api/v1/auth`, and your `router()` is merged at `/api/v1`. Use the paths `/invites/{token}` and `/invites/accept` (served as `/api/v1/invites/...`) to avoid the nest collision. Note the final paths in your log.
- PATCH `/exams/{id}/enrollments/{candidateId} {extraMinutes}`: an accessibility accommodation, audited. DELETE sets status revoked, even mid-exam; a revoked candidate can't start.
- `GET /exams/{id}/enrollments` returns `Enrollment[]` with the real attempt summary, `invited` (any invite row exists) and `activated` (password_hash is not null).
- Web: build `web/src/app/(auth)/invite/[token]/page.tsx` (plus any client component under that folder), an accept-invite screen in the existing auth style (study `web/src/app/(auth)/login` and `web/src/components/auth/*`).
  - Fetch the invite, ask for a display name and a password (with the existing strength meter component), post accept, then `router.replace("/app")`.
  - Error states: an expired or used invite shows "Ask your examiner for a new invite"; also cover network errors.
  - Call `/api/v1/invites/...` through `api()`.
- Tests:
  - a dry run writes nothing
  - one bad row blocks the whole import
  - another examiner's exam gives 404
  - an invite can be used once only
  - an expired invite is rejected
  - accept sets a session cookie
  - examiner emails are refused as candidates
- Expose `pub async fn enroll_tx(tx, exam_id, rows, by)` for C8's seed.
