# H8 log: auth screens and public verification radar

## What changed

**1. Password animation on login and invite**
- `web/src/config/site.ts`: `authSet` is now `1` (Editorial). Set 1 is the set with the padlock, and its login
  already had the masthead layout, the strip form and the demo panel. Its forgot, reset and verify screens
  (keys, vault, envelope) are used by the real routes too. Set 2 (owl) is no longer the default.
- `web/src/components/auth/password-lock.tsx` (new): a `PasswordLock` that plays `/lottie/padlock.json`.
  - The shackle is scrubbed by password length: 12 characters or more runs the full cycle. The position
    eases toward its target at about 20% per frame.
  - `state="pending"` spins the lock on a loop while the sign-in or activation request is in flight.
  - Colours come from the theme tokens, the same way `LottieLoop` does it. The retheme helper is copied
    because `LottieLoop` does not export it.
  - Reduced motion jumps to each position and never spins. Off-screen pauses the player.
- `web/src/components/auth/set-1/login.tsx`: the masthead padlock is `PasswordLock`, fed by
  `LoginForm`'s `onValues` (length only, the password never leaves the form) and `onStatus`. The old
  `LottieLoop` padlock did not react to typing at all, so this is new behaviour.
- `web/src/app/(auth)/invite/[token]/invite-form.tsx`: a `PasswordLock` (vermilion panel) sits under the
  heading. It follows the password and spins while the account is activated. The API calls, error messages,
  redirect and `StrengthMeter` are unchanged.
- Copy: placeholder `you@studio.com` changed to `you@institution.edu` in `forms/login-form.tsx`,
  `forms/forgot-field.tsx` and `forms/signup-form.tsx`. The duplicate "Accounts are created by your
  institution." line was removed from the demo panel. The form still shows it once.
- Kept: the demo panel (`login/demo-accounts.tsx`, three "Sign in as …" buttons that fill and submit the
  real form), no self-signup link, no social buttons, no "Try the demo".

**2. Verification radar**
- `web/src/components/auth/certificate-check.tsx` (new, client): shared by both routes.
  - The radar's six contacts map to every second character of the 12-character code, so they fill as the
    code is typed. Typing sets the radar to `listening`.
  - Fetching sets `checking` (scanning). A valid result sets `locked`. An invalid or revoked result sets
    `wrong`, which bursts the no-match static. A network error keeps `listening`.
  - The result card is unchanged: masked statement, "Signed with Ed25519 · key …", the privacy text, and
    the same API call (`/verify/{code}`).
  - The canvas is `aria-hidden` (AsciiCanvas does this). The status line is a DOM `role="status"` with
    `aria-live="polite"`, reading "Checking the signature", "Certificate valid, signature checked",
    "Certificate revoked", "No valid certificate for this code", "Reading the code, n of 12", and so on.
  - Submit still navigates with `window.location.assign`, as before, so a stale result cannot linger.
- `web/src/app/verify/page.tsx` and `web/src/app/verify/[code]/page.tsx`: now thin server pages with
  metadata. The `[code]` page awaits `params`, as the invite route does.
