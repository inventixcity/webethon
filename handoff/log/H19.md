# H19: login masthead, two-column fit, marquee removal

## Done
- **Masthead (`components/auth/set-1/login.tsx`)**: one tight phrase, "Back [padlock] in.", left-aligned, with normal word spaces (`{" "}` between the three `Reveal`s). The old `justify-between` spread is gone. The padlock tile is an inline-block `size-[0.7em]` on the baseline, so its top sits at cap height. It still follows the password through `PasswordLock`.
- **Font size**: set with an inline style, `clamp(72px, min(15vh, 24vw), 184px)`, not an arbitrary Tailwind class. The 17.png shot showed the masthead at about 18px, which points to the class not applying. I did not pin the exact cause, because the dev server was returning 500 at the time. The inline style is immune to that. Measured: 108px at 720 high, 135px at 900, 144px at 960, 162px at 1080. Never below 72px.
- **Layout**: two columns from md up (`md:grid-cols-[minmax(0,1fr)_clamp(16rem,30vw,28rem)]`), where it was `lg:` before. The right column is the full-height `login-side` art. `auth-screen.tsx` now passes `className="absolute inset-0"` into a `relative` wrapper, so the art fills the column and never drops to a bottom strip. It is hidden below md, and phones scroll.
- **Marquee removed from all auth screens**, per the coordinator's rule. Removed the `Ticker` from set-1 and set-2 login, forgot, reset and signup. Set-1 and set-2 signup also lose their vertical ticker rail, and their grid drops the 3rem column. Sets 3 to 6 had no Ticker.
- **Buttons**: every auth button already uses the shared `Button` or `SubmitButton`, so the wipe applies to Sign in, the demo "Sign in as ...", Verify code, Accept invite and Continue. No raw `<button>` remains in the auth tree. The `link` variant (Show/Hide, Resend, Use a different email) has no fill, so it has no wipe by design.
