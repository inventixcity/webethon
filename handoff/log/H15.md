# H15 log: verify pages (/verify, /verify/[code]) layout and navigation

## Done
- **Layout** (`web/src/components/auth/certificate-check.tsx`): one viewport on laptop sizes (lg and up). Left 5 of 12 columns: eyebrow `VERIFY / CERTIFICATE`, headline "Check a result.", one-line explainer, code input with the Verify button, status line, then the result card. Right 7 of 12: the radar as the hero, vertically centred, in a hairline frame with a `SIGNAL / ED25519` caption and a live state label (Listening, Scanning, Locked, No match). `verify-bg` sits behind the radar at 15% opacity, greyscaled.
- **Phones**: the radar is a band above the form (`order-first`), not at the bottom.
- **Result card**: status band. Valid is cobalt, revoked is amber, invalid is vermilion. The band uses `data-theme="light"`, so its text pairs hold in both modes. The card body shows masked candidate, result (percent and pass), examination, issued date, certificate ID, the `Signed with Ed25519 · key …` line and the privacy explanation. Surfaces are token-based (black shades in dark mode).
- **Radar states**: scanning while typing (700 ms after the last keystroke) or fetching, locked on valid, no-match burst on invalid or revoked. The old `setStatus("listening")` on input is removed, so typing no longer fights the state.
- **Navigation**: `web/src/app/verify/layout.tsx` (new) wraps both pages with a top bar, `web/src/components/verify/verify-top-bar.tsx` (new). It has the Invigil mark (link to `/`), a Back button, a Sign in link (`/login`) and the theme toggle.
- **Smart Back** (`web/src/components/verify/smart-back.ts`, new): `router.back()` when `window.history.length > 1` and either the current history entry is app-router-made (`history.state.__NA`) or `document.referrer` is same-origin. Otherwise it pushes `/`.
- **Exit row** on the code page: "Check another code" pushes `/verify`, which clears the code and resets the radar, and a Back button uses the same smart Back.
- **Submit** now uses `router.push` instead of `window.location.assign`, so Back from the result returns to the input page. `[code]/page.tsx` passes `key={code}`, so a new code never shows the previous result.
- **Kept as specified**: `api<VerificationResult>(\`/verify/${encodeURIComponent(code)}\`)`, the code mask, the status and result statements, the Ed25519 line and the privacy text.
- **Date handling**: `issuedAt` can arrive as a time-crate tuple (see requests below). `issuedLabel()` reads both that and ISO strings, so the page never shows "Invalid Date".

## Open gaps
- Back behaviour is by inspection. I did not drive a browser through click paths (candidate page → verify → Back). The `__NA` check relies on Next's internal history-state flag. A direct load of a cross-origin referrer in a tab with earlier history will go back to that earlier entry, which is the browser's own previous page.
- Revoked (amber) and invalid (vermilion) bands are not screenshotted (see above).
- Reduced motion relies on AsciiCanvas and the radar's existing reduced branch. I did not test it with emulation.
