- Requests to lead:
  1. `useAttempt().submit()` (C5) swallows errors: it sets `error` and does not rethrow. The workspace works around this by waiting for `closed` (success) or a new `error` (failure). Preferred fix: rethrow after setting state, so the dialog can show failure directly.
  2. `useTypingTelemetry()` (C7) keeps `counters` and `current` inside the hook body, so each render discards them. `onKeyDown` and `onPaste` close over a fresh `current`. Workaround here: `useRef(useTypingTelemetry()).current`, which keeps one instance per written question. C7 should keep state in a `useRef` (or be documented as a non-hook factory) and return stable handlers.
  3. `device.ts` exports `deviceId()` (synchronous, empty string on the server). The workspace reads it in an effect. Fine as is.
  4. `use-attempt.ts` returns `network`, but the workspace uses `useNetworkStatus()` as the spec says. The two stay in step because both use the same quality logic.
  5. `useAttempt` must return `payload.canary` as typed (`string | null`), which the workspace reads directly.
